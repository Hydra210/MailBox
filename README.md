# Mailbox

A private, inbound-only mailbox dashboard for domains you own. The app is designed to run on Render, with Cloudflare Email Workers acting as the inbound email gateway.

## What it does

- Private admin sign-in
- Add multiple custom domains
- Create individual inboxes or numbered batches
- Receive and store inbound messages and attachments
- Search, read, and delete messages
- Dark, responsive dashboard
- No outbound email sending

Use this for mailboxes and aliases you control, and follow the terms and verification rules of the services you use. The app does not automate account creation or bypass third-party limits.

## Architecture

Cloudflare Email Routing invokes the email Worker in `cloudflare-worker/`. The Worker forwards the original RFC 5322 message over HTTPS to the Render app's `/api/inbound` endpoint. The app parses MIME and stores messages in PostgreSQL.

Render does not receive SMTP directly. No outbound SMTP is used.

## Important hosting note

The included Blueprint uses Render's free web service and free PostgreSQL plan for an initial test deployment. Render's free web services sleep after 15 minutes idle, and free PostgreSQL databases expire 30 days after creation. Free PostgreSQL is capped at 1 GB and has no backups. **Do not use the free database for mail you need to retain.** Upgrade to a paid database before relying on it, or arrange regular exports. Check current Render pricing before applying a Blueprint.

## Deploy on Render

1. Open the repository's Render Blueprint flow.
2. Review the proposed resources and prices before applying.
3. Set `ADMIN_PASSWORD_HASH` as a bcrypt hash of your chosen admin password. Generate one locally with:
   `node -e "require('bcryptjs').hash(process.argv[1], 12).then(console.log)" "your-long-password"`
4. Keep `SESSION_SECRET` and `INBOUND_SECRET` generated by Render. Do not put their values in GitHub or share them in chat.
5. Apply the Blueprint and wait for the web service to become healthy.
6. Open the service URL and sign in.

If you change the service URL, update `APP_ORIGIN` in Render and use that URL for Cloudflare's `MAILBOX_INGEST_URL`.

## Cloudflare setup

For each domain:

1. Make sure the domain is active in your Cloudflare account and its nameservers point to Cloudflare.
2. In Cloudflare Email Routing, enable inbound routing for the domain and create a catch-all route that invokes the Worker deployed from `cloudflare-worker/`.
3. Deploy the Worker. Set these Worker environment values:
   - `MAILBOX_INGEST_URL`: `https://YOUR-RENDER-SERVICE.onrender.com/api/inbound`
   - `MAILBOX_INBOUND_SECRET`: the same secret value as Render's `INBOUND_SECRET`
4. Configure the domain's Email Routing MX records exactly as Cloudflare instructs. Do not add guessed MX records.
5. Add the domain in the Mailbox dashboard, then create the inbox addresses you want to receive mail at.

The catch-all Worker passes the actual envelope recipient to the app, so a single Worker can deliver messages for many mailbox addresses on that domain.

## Local development

Requires Node.js 20+ and PostgreSQL.

```bash
npm install
```

Set the following in a local `.env` file (never commit it):

- `DATABASE_URL`
- `SESSION_SECRET`
- `INBOUND_SECRET`
- `ADMIN_PASSWORD_HASH`
- `NODE_ENV=development`

Then run `npm start`.

## Security notes

- Use a strong, unique admin password.
- Keep both secrets private and rotate them if exposed.
- Email content is untrusted. The UI displays plain text by default and isolates HTML in a sandboxed iframe.
- Attachments are stored in PostgreSQL as base64 data. This is convenient for small personal use, but increases database usage; keep an eye on database storage.
- The app accepts inbound messages up to the platform's configured request limit. Cloudflare Email Routing currently documents a 25 MiB inbound message limit.
- Add only domains you own or are authorized to manage.
